# 限制文件修改范围

此skill用于限制文件修改操作只能作用于当前工作目录，其他目录下的文件仅提供阅读权限。

## 何时使用此skill

当用户表达以下意图时使用此skill：

- 要求"只能修改当前工作目录下的文件"
- 要求"其他目录下的文件只有阅读权限"
- 要求"限制修改范围"
- 要求"不要修改其他目录的文件"
- 表达类似的安全限制意图

## 执行规则

### 文件读取操作

- 所有目录下的文件都可以读取（read、grep、glob、codesearch、websearch、webfetch 等）
- 无任何限制

### 文件修改操作

对于以下写操作，需要进行路径检查：

- **write** - 写入文件
- **edit** - 编辑文件
- **bash** 中的文件创建/修改命令（如 mkdir、touch、cp、mv、rm 等）

### 路径判断逻辑

1. **获取当前工作目录**：从环境变量 `workdir` 获取，或使用 Bash 工具的 `workdir` 参数值作为当前工作目录
2. **检查目标路径**：
   - 如果目标路径是当前工作目录的子目录或文件 → 允许执行
   - 如果目标路径在当前工作目录之外 → 拒绝执行，只提供阅读
3. **路径标准化**：将目标路径转换为绝对路径后再进行比较判断

### 拒绝执行时的响应

当用户要求修改非工作目录下的文件时，回复示例：

```
抱歉，我只能修改当前工作目录（<当前工作目录路径>）下的文件。
其他目录的文件我只有阅读权限，无法进行修改。

如果您需要修改其他目录的文件，请将工作目录切换到目标目录后重试。
```

## 示例场景

| 用户请求 | 处理方式 |
|---------|---------|
| 修改 {workdir}/src/app.js | 允许执行 |
| 修改 {workdir}/../other/file.txt | 拒绝执行，仅提供阅读 |
| 删除 {workdir}/tmp/test.txt | 允许执行 |
| 修改 /etc/config.conf | 拒绝执行，仅提供阅读 |

**注**：以上示例中的 `{workdir}` 表示当前工作目录的实际路径，由环境变量或配置动态提供。
